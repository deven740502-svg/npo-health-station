# 健康站：給小型服務單位用的健康量測紀錄系統

<!-- 截圖放這 -->

## 這是什麼

這是一套給身心障礙服務單位（工坊、日間服務、社區據點）記錄服務對象每日健康量測的系統。體重、血壓、血糖、脈搏、情緒行為，量完直接在平板上按幾下就好，月底可以直接印出報表。

整套系統就是一個 `index.html` 檔案，沒有伺服器要架、沒有東西要安裝，資料存在 Google 的 Firebase 上。丟到 Netlify 就能用。

它現在正在兩個工坊每天實際使用中。

## 為什麼把它公開釋出

這套東西的價值不在程式碼。

它的價值在於：服務對象自己按下按鈕、看見自己的血壓數字、知道今天要不要複測。量測這件事從「工作人員操作」，變成「服務對象自己做、工作人員在旁邊協助」。這個轉換不需要很貴的系統，但需要有人先把它做出來。

我們有幸做出了一些雛型架構，AI 時代來臨，應該讓服務對象有機會更多的參與與自主，所以我們選擇公開釋出。任何機構都可以拿去改成自己的樣子：改單位名、改欄位、改流程、改成完全不一樣的東西都行。唯一不行的是拿去賣，授權細節見文末。

## 我們不接 issue，也不接 pull request

我們沒有維護人力。這套系統是白永恩基金會台南辦公室鄭智文主任為了解決小作所服務上遇到的痛點做的，沒有工程團隊，沒有人有時間看 GitHub 通知。你開了 issue，它不會被處理；你送了 PR，它不會被合併。與其讓你等一個不會來的回覆，不如直接講清楚。

但這不代表你只能自己摸索。**把整個 `index.html` 丟給你的 AI（Claude、ChatGPT、Gemini 都可以），告訴它你要改什麼。** 它讀得懂。我們刻意把這個檔案切成一個一個有名字的區塊，檔案開頭還放了一份區塊地圖，就是為了這件事。

三個可以直接複製去問的例子：

> 這是一個單檔 HTML 的健康量測系統，檔案開頭有區塊地圖。我要把「單位」從兩個改成四個，請告訴我要改哪幾個地方，並把改好的完整程式碼給我。

> 這是一個單檔 HTML 的健康量測系統。我想在健康量測裡多加一個「血氧」欄位，跟血壓一起輸入、一起顯示在報表上。請幫我改，並說明你動了哪些區塊。

> 這是一個單檔 HTML 的健康量測系統，血壓有兩階段複測的判斷邏輯。請先讀懂那段邏輯並用白話解釋給我聽，我還不確定要不要改。

第三個是最推薦的用法：**改之前先叫 AI 解釋給你聽**。

## 五分鐘跑起來

### (a) 開一個 Firebase 專案

到 [Firebase Console](https://console.firebase.google.com) 建立專案。名字隨便取，不用開 Google Analytics。

### (b) 開 Firestore 與 Authentication

- **Firestore Database** → 建立資料庫 → 選離你最近的區域（台灣選 `asia-east1`）→ 先選「以測試模式啟動」，等一下會換成正式規則
- **Authentication** → 開始使用 → 登入方式選 **電子郵件/密碼**，啟用

### (c) 建帳號

在 Authentication → Users → 新增使用者。這個系統一個單位一個帳號，密碼就是工作人員在登入頁按的 7 位數字：

| 帳號 | 密碼 | 誰用 |
|---|---|---|
| `sunny@health.local` | 7 位數字 | 陽光工坊的工作人員 |
| `river@health.local` | 7 位數字 | 河岸工坊的工作人員 |
| `admin@health.local` | 你自己設 | 系統管理員（新增單位、看垃圾桶） |

`@health.local` 不是真的信箱，寄不到也收不到。Firebase 的登入方式要求帳號長得像 email，所以給它一個 `.local` 結尾的假網域。這個結尾是保留給區域網路的，不可能被誰註冊走。

單位帳號的前綴（`sunny`、`river`）就是「單位代號」，後面改單位時會一直用到它。

### (d) 填 Firebase 設定

Firebase Console → 專案設定 → 你的應用程式 → SDK 設定與配置，把六個值抄下來，填進 `index.html` 開頭的這段（搜尋 `YOUR_API_KEY` 就找得到）：

```js
window.FIREBASE_CONFIG = {
  apiKey: "YOUR_API_KEY",
  authDomain: "YOUR_PROJECT_ID.firebaseapp.com",
  projectId: "YOUR_PROJECT_ID",
  storageBucket: "YOUR_PROJECT_ID.firebasestorage.app",
  messagingSenderId: "YOUR_SENDER_ID",
  appId: "YOUR_APP_ID"
};
```

順手再搜尋一次 `YOUR_PROJECT_ID`：系統管理員畫面裡有一個連到 Firebase Console 的按鈕，網址裡也有這個值，一起換掉。

> 這六個值放在網頁裡是 Firebase 的正常用法，不是密碼。真正擋住別人的是下一步的規則。

### (e) 貼上 Firestore 規則

把 `firestore.rules` 的內容整份貼到 Firebase Console → Firestore Database → 規則 → 發布。

**這一步不能跳過。** 測試模式的規則是「任何人都能讀寫」，30 天後會自動關閉，而且在那之前你的資料是完全公開的。

### (f) 建一個索引

Firestore Database → 索引 → 複合式 → 新增索引：

- 集合 ID：`records`
- 欄位：`patientId`（遞增）、`timestamp`（遞減）

沒有這個索引，報表頁會查不到資料。（也可以先不建，開報表時 Console 會跳出錯誤訊息，裡面附一個一鍵建立的連結。）

### (g) 丟上 Netlify

到 [Netlify](https://app.netlify.com) → Add new site → Deploy manually → 把整個資料夾拖進去。

**只要放 `index.html` 和 `assets/` 資料夾。** 其他檔案（README、LICENSE、firestore.rules）拖上去就會變成公開網址上的檔案，沒必要。

打開網址，應該就會看到選單位的畫面了。

## 改成你們的樣子

### 改單位名稱與代號

「單位代號」（`sunny`、`river`）出現在這些地方，改的時候要一起改：

| 在哪裡 | 是什麼 |
|---|---|
| `index.html` 登入頁的兩個 `<button onclick="selectWorkshop('sunny')">` | 登入頁的靜態備用按鈕 |
| `index.html` 的 `var WORKSHOPS` | 登入頁用的單位清單（登入前就要顯示，所以獨立一份） |
| `index.html` 的 `DEFAULT_WORKSHOPS` | 讀不到 Firestore 時的備用值 |
| `index.html` 的 `getWorkshop()` | 網址沒帶參數時的預設單位 |
| `index.html` 的 `appName` | 頁首標題（見下方「多於兩個單位」） |
| Firebase 的帳號 | `<單位代號>@health.local` |
| 網址 | `你的網址/?workshop=sunny` |

`firestore.rules` **不用改**，裡面用的是萬用字元，任何單位代號都吃得下。

單位建好之後，也可以用系統管理員帳號在畫面上直接新增、改名、停用單位，不必再動程式碼。

### 多於兩個單位的時候

頁首標題那行目前是硬寫死的兩選一：

```js
const appName = workshopId === 'river' ? '河岸工坊健康站' : '陽光工坊健康站';
```

超過兩個單位就會顯示錯名字。正確的寫法是從單位清單查表。這行程式碼上面有註解標出來了，把整段丟給 AI 說「改成查表」就會了。

### 換 logo

我們把原本的 logo 拿掉了（那是我們機構的，不能給你用）。`index.html` 裡有兩處註解標了插回位置，搜尋 `想放自己的 logo` 就找得到：登入頁的置中大圖，和頁首左側的小圖。把圖片檔放進 `assets/`，把註解拿掉、換成你的檔名就好。

沒有 logo 也完全能用，畫面不會壞。

想生一個？把下面這段貼給會畫圖的 AI：

> 請畫一個社福機構的 logo，圓形或方形構圖，只有一個主要圖形，線條簡潔、留白多。主題是「照顧」與「日常生活」，可以是一雙手、一片葉子、一個屋簷，不要用醫療器材或十字符號。單一顏色（深綠或暖橘），背景透明，扁平風格不要漸層、不要陰影、不要立體效果。不要有任何文字。輸出 512×512 PNG。

生出來存成 `assets/logo.png`，再把兩處的檔名改掉。

### 換顏色

單位的主色在 `WORKSHOPS` 與 `DEFAULT_WORKSHOPS` 裡（`color`、`bgBorder`、`textColor` 那幾欄）。整體配色用的是 Tailwind CSS 的顏色名稱，直接跟 AI 說「把橘色系換成藍色系」比自己找快。

### 換字型

頁首標題用的是「清松手寫體 2」，`assets/` 裡放的是子集檔。為了讓檔案小（6KB 而不是 1.7MB），我們只把「陽光工坊健康站河岸智慧點餐」這 13 個字放進去。

**你把標題改成別的字，那些字就會掉回備用字型（Noto Serif TC）。** 版面不會壞，只是變成一般的明體。

想讓自己的單位名也用手寫體，用 [fontTools](https://github.com/fonttools/fonttools) 重新子集化一份：

```bash
pip install fonttools brotli
# 先把你要的字寫進 chars.txt（例如：向陽工坊健康站）
python -m fontTools.subset JasonHandwriting2.ttf \
  --text-file=chars.txt \
  --output-file=assets/JasonHandwriting2-subset.woff2 \
  --flavor=woff2 --no-hinting --desubroutinize --layout-features=
```

字型原檔到 [清松手寫體](https://github.com/jasonhandwriting/JasonHandwriting) 下載。它是 SIL OFL 授權，可以自由散布，但**要把 `assets/OFL.txt` 一起留著**。

#### 想換成別的字型

手寫體只是我們的選擇，不是規定。你可以換成任何一套字型，做法一樣是把需求丟給 AI，但換之前先想過這四件事：

1. **授權**：網路上下載得到不等於可以放進你的網站散布。Google Fonts 上的字型全部可以用；標 SIL OFL 或 Apache 授權的可以用；買來的商用字型多半不行，要看授權書有沒有寫「網頁嵌入」。拿不準就問 AI「這套字型的授權可不可以嵌進公開的網站」，並把授權全文貼給它看。
2. **檔案大小**：一套完整的中文字型通常 5 到 20 MB，直接放進去會讓網頁在 iPad 上開很久。要嘛像我們一樣只打包用到的字，要嘛改用 Google Fonts 線上載入（不用放檔案，但沒有網路時會退回備用字型）。
3. **好不好讀**：這個標題是給服務對象和工作人員看的，不是給設計師看的。手寫體、圓體、藝術字在大字級當標題還可以，內文請維持一般黑體或明體。換完之後請一位服務對象看一眼，比任何設計原則都準。
4. **備用字型要留著**：`@font-face` 後面的 `'Noto Serif TC', serif` 是安全網，字型檔壞了或字不在包裡，版面才不會開天窗。叫 AI 改的時候，明確說「備用字型鏈不要動」。

可以直接複製去問的一段：

```
這是一個單檔 HTML 的健康量測系統，頁首標題目前用一套子集化的手寫體（@font-face 載入 assets/ 裡的 woff2）。
我想把標題換成「（字型名稱）」。請先告訴我：這套字型的授權能不能嵌進公開網站、完整檔案大概多大、
要不要子集化。確認後再給我要改的程式碼，備用字型鏈 'Noto Serif TC', serif 不要動。
```

或者你也可以整段不要：把 `index.html` 裡的 `@font-face` 那幾行刪掉，字型就一律用 Noto Serif TC。

## 架構說明

### 為什麼是單一個 HTML 檔

沒有 npm、沒有 build、沒有框架安裝。React 和 Firebase 都是從 CDN 直接載入，JSX 由瀏覽器裡的 Babel 即時編譯。

**這樣的好處**：任何人打開檔案就能改，改完存檔重新整理就看到結果。不會有「三年後想改一行字，結果依賴裝不起來」的問題。這對沒有工程人力的機構是決定性的。

**代價**：第一次開頁面要多花一兩秒編譯；檔案有四千行，靠區塊註解和搜尋來導覽；沒有自動化測試。

我們認為對這個規模的系統來說這筆交易划算。你如果有工程人力，把它拆成正常的 React 專案也完全合理。

### 區塊地圖

`index.html` 開頭有一份區塊地圖，列出所有具名區塊。在編輯器搜尋 `// 【` 可以逐一跳到。這是給你、也是給你的 AI 用的導覽。

### 資料放在哪

```
artifacts/health-station/workshop_configs/{單位代號}     ← 單位清單（名稱、圖示、顏色、是否啟用）
artifacts/health-station/{單位代號}/data/patients/       ← 服務對象基本資料
artifacts/health-station/{單位代號}/data/records/        ← 每次量測紀錄
artifacts/health-station/{單位代號}/data/medications/    ← 藥物資料庫
artifacts/health-station/{單位代號}/encryptionKey        ← 這個單位的加密金鑰
```

路徑裡的 `health-station` 是 `index.html` 的 `dbAppId` 常數。**改了它就要同步改 `firestore.rules` 裡的三處路徑**，兩邊對不上就什麼都讀不到。

各單位的資料是完全隔開的：規則層檢查你的登入帳號 email 前綴是不是等於路徑上的單位代號，不是就整個擋掉。

## 誠實說明的限制

這一節寫的是我們知道、但沒有解決的事。拿去用之前請先讀。

### 單位清單是公開可讀的

`workshop_configs` 集合任何人都讀得到，因為登入頁在登入之前就要顯示單位清單。裡面只有單位名稱、圖示、顏色、是否啟用，沒有個人資料。要改單位設定則必須先登入，另外前端還有一道系統管理員密碼門。

這是一個取捨，不是安全設計。如果你的單位名稱本身就是敏感資訊，這套做法不適合你。

### 加密只加了一部分

服務對象的**姓名、生日、用藥清單**在寫進 Firestore 之前會過 AES-GCM 256-bit 加密，金鑰存在 Firestore 裡、由程式第一次執行時自動產生，程式碼裡沒有金鑰。

**照片沒有加密**，以 base64 明文存在 Firestore。這是我們評估後刻意保留的：照片在畫面上到處都要顯示，加密會讓每次列表渲染都要解一次。你如果覺得不能接受，這是一個值得改的地方。

金鑰存在 Firestore 意味著：**能讀到資料庫的人也能讀到金鑰**。這層加密防的是資料庫被匯出、備份外流這類情境，防不住帳號被盜。

### 照片吃 Firestore 單筆 1MB 上限

照片存成 base64 塞在服務對象的文件裡，Firestore 單筆文件上限 1MB。程式有壓縮，但如果你要放很多張或很大張，這個架構會撞牆。要解的話得改用 Firebase Storage。

### 血壓的閾值看起來互相矛盾，那是刻意的

程式裡有三組血壓數字，不要「順手把它們統一」：

| 用在哪 | 數字 | 為什麼 |
|---|---|---|
| 初測是否要複測 | 收縮壓 ≥ 140 或舒張壓 ≥ 90 | 這是「篩出來下午再量一次」的門檻，設寬一點才不會漏 |
| 複測的判讀標準 | 收縮壓 ≥ 130 或舒張壓 ≥ 80 | 已經是第二次量，標準收緊 |
| 隔天卡片的警示分級 | 160/100 → 很高、140/90 → 偏高 | 這是給工作人員看的提醒強度，不是臨床判讀 |

這是兩階段篩檢的設計：第一關寬、第二關嚴、提醒又是另一回事。曾經有人提議把三組統一，被否決過。你要改可以，但請先確認你改的是哪一關。

取「複測優先」值的地方一律走 `pickRecheck()` 這個函式（有複測值就用複測值，沒有就用初測值）。報表表格上「初測／複測」並列顯示是刻意的，只有色塊、圖表、警示 badge 才用複測優先值。

### 其他

- 沒有自動化測試。改完請自己點一遍。
- 沒有多語言。畫面全是繁體中文寫死的。
- 資料匯出只有列印和另存 PDF，沒有 CSV。
- 系統管理員的密碼門是前端的一道門，真正的權限邊界在 Firestore 規則。
- 用 CDN 載入 React 與 Tailwind，代表使用時需要網路，而且那幾個 CDN 掛掉你的系統就開不起來。在意的話要把它們改成放在自己站上的檔案。
